4CO Work Center — Operations Playbook

Reminder & teaching guide · scenarios → screens → what happens behind the curtain · current as of July 31, 2026

0 · One rule for order numbers

Whoever issues the document owns the number. Work orders, sales orders and invoices lead with the NetSuite number (WO11312, SO59176, invoice #) the moment it exists — the long app id shows only until then, and stays available on hover. Purchase orders and quotes keep the app's short numbers (PO-1044, QUOTE-…) because the app is the source for those.

If a screen shows a long WO-STK-… string, the NetSuite work order simply hasn't posted yet (~1 minute after RTG release).

1 · Sales Snapshot (HQ 12.5) — planning & ordering

Reading the grid

  • Min OH rules: OUT (outsourced: vendor, no assembly) = 6 months of demand. ASM (in-house assembly) = 6 weeks (3wk finishing lead + 3wk safety). Everything else = 4 weeks of the 6-month rate.
  • ROP is the FLOOR under Min OH, not an override (changed 07/28/26). A brand-new item has no sales history, so the demand rule computes ~0 and the item reads as fully stocked at zero — the ROP you typed stands in and Min OH shows it in brass. Once real demand climbs above the ROP the calculated figure takes over by itself. Short and Rec always measure against the number shown, so the columns can't disagree. A ROP set BELOW the demand rule no longer holds the threshold down. ⬆ Save pushes edited ROPs to the Master Library.
  • Raw Cores (BOM) view: demand rolled up to the raw base behind the finish variants — set core ROPs here so finishing never runs out of metal. Ordering always happens from the Finished view.
  • Ring packs: the -EA single row carries ALL demand (each-buyers + packs). Pack rows (-7/-10/-12) are analysis-only — order the single, packs build themselves at pick.
  • Sort: Item # / Finish — Finish groups /SG · /N25 · … together so you can issue all same-finish work orders in one pass (they arrive at the Setup Queue already batched).

Ordering

  1. Enter Order quantities (Rec is guidance, never auto-filled).
  2. ⚙ Generate Orders: bought items → ONE PO per vendor; made items → work orders parked in RTG (nothing reaches the floor unreviewed).
  3. The snapshot loads the WHOLE catalogue (fixed 07/28/26). SuiteQL returns 1,000 rows per response and the item query never paged, so past 1,000 stocked+old items everything after the cut simply did not exist here — no history, no rollup, no tier family. If a row count ever sits suspiciously near a round number again, that is the shape of the bug.
  4. Sourcing decides the lane, and it is never guessed. An item set Both in the Master Library — we make it and we buy it — always stops at the vendor step and asks, pre-selected to ⚒ make in-house, so doing nothing gives you the work order. Rows carry a ⚖ BOTH → ASK chip so you see it before you generate. An assembly is built here and never becomes a PO candidate, whatever its in-house flag says.
  5. Short on raw cores? Tap the row's ⇄ to attach a convert suggestion (pick a sister finish with shelf stock + qty). It rides the WO to the Setup Queue — the floor executes it, the snapshot never posts anything.
  6. ✂ on 8-ft rods — cut orders route to WMS ROD CUTS and post the 2-line NetSuite adjustment at scan.

3-Tier view (raw · /P · plated) — added 07/28/26

For families stocked at three levels (Fabricut H1): the raw mill core, the /P phosphated base that feeds every in-house paint, and the /EP plated tiers. They only make sense read together, so the view shows one block per family — the raw core as the header (with its description), its tiers indented beneath, /P first.

  • A family appears once its “/P” item is stocked alongside the raw core. Plain raw cores stay on the Raw Cores view.
  • Tier is read off the suffix, never asked: /P = phosphate · a suffix matching a configured Outsourced Master Finish (EP1, EP2…) = plated · anything else = finished goods.
  • Every tier has its own Order box, because they are genuinely different work. The Routes to column shows the destination before you generate.

Convert and plating both eat the raw core. If what you're asking for exceeds the raw on hand + on order + whatever you typed on the raw row, the confirm box names the family and the shortfall. It does not quietly add a work order — the raw row is right there on the same screen and a silent extra WO would double-order it.

The /P to-do is closed by the CONVERT tab: “Pull & Convert →” opens the cart pre-filled, the raw moves to the phosphate cart bin, and the to-do clears only when the assembly build actually posts. Plated to-dos ride the normal weekly plater shipment and PO (§7).

When the snapshot looks empty

A blank screen names its own cause now — read the counter line before re-tagging anything.

  • N stocked rows loaded · N contain “…” · N have no Master Library part — plus the specific gate that failed.
  • The row universe is NetSuite's Stocked box (custitem27), read live. The app's own “Stocked finished assembly” checkbox is a different field — it tells CPQ to push the finished assembly, it only ever copies down from NetSuite, and ticking it cannot put an item in this report. Tick it in NetSuite (or push it up — §10), then just re-open the snapshot; no re-sync needed.
  • Category / collection / watchlist read the Master Library part, not the NetSuite row — an unlinked row can never match one of those filters however it's tagged in NetSuite. Clear the filters and search the item # instead.
  • In the 3-Tier view a family surfaces when any of its tiers carries the filter you picked, and then shows all of them — so the collection only has to be on the /P or an /EP.

📋 Open WOs (cleanup panel)

Button in the snapshot toolbar. Every not-closed WO with floor phase + coat, task mini-status, NetSuite WO/BUILD state, pack status.

  • ↩ Reset → Setup — rewinds a floor order to "picked, ready for setup" and clears completion/pack/NetSuite-build stamps. Use after deleting a wrong Assembly Build in NetSuite: the real completion will re-post. Never touches the NetSuite work order.
  • ✕ Close — soft-closes app docs and queues the NetSuite WO close when safe.

2 · RTG Dispatch — the control gate + NetSuite window

  • Push to Finishing releases the pre-built floor doc verbatim AND creates the real NetSuite work order (staged write). One NetSuite WO per app WO, ever — re-releasing an already-dispatched order needs a second scary confirm and never duplicates the WO.
  • NetSuite Transmit Log (bottom of RTG): every staged write with live status. Click a row → CALLED (exact REST path), SENT (payload summary), NETSUITE SAID (the real error text). ↻ Re-queue retries with known fixes applied. Red banner = the queue worker isn't running → Cloud Shell deploy.
  • Full queue with Retry/Cancel lives in 11.1 → NetSuite Sync Queue. Retries keep the attempt count so the worker first checks NetSuite for an already-posted copy — hammering Retry can never double-post.
  • Finding old duplicates in NetSuite: true twins share the same memo marker ([app push 07/20/26, 2:32 PM #aVNdVI]). Global-search the marker; every hit past the first is a twin to delete.

3 · Finishing — Setup Queue

  • Orders group by finish (dark headers) — run each batch together, earliest section first.
  • ▶ Start Setup releases the parts pick to WMS. Custom orders send their BOM small parts; stock builds send the raw base pull (finish suffix stripped, qty = build count). The card chip tracks it: awaiting release → in pick queue → picked.
  • ⇄ Convert Finished → Raw (top of screen): out of raw cores? Enter the raw #, Find Stock shows the raw + every finished variant with live per-bin counts, pick a donor + qty + bins, ⚡ Convert posts the 2-line NetSuite adjustment immediately. Packs excluded — unbuild packs in WMS first.
  • ⟲ Scrap Re-make: item # + qty + reason → creates the same RTG-parked stock WO the snapshot makes (flagged remake). Use it the moment QC reports scrap.
  • Brass strip on a card = the planner's convert suggestion — run it with the ⇄ tool above.
  • ✕ per card = safe close (queues the NetSuite WO close when one exists un-built).

4 · Finishing — Active Floor

Poles and small parts move on their own tracks. Painting them together is the ideal — the app suggests, never blocks. Parts advance by "Unload Parts"; poles advance by "Next Pole Coat" on their own pointer. An order completes only when BOTH tracks pass the last coat.
  • Tap any job window (task card title, pole card, pipeline row) → read-only details: NetSuite WO, item, qty, parts coat n/m, poles coat n/m, task grid, notes.
  • Tap a station on the twin — RED sled, BLUE sled, OVEN, POLE RACK, HAND FINISH — for 🎛 manual controls: ▶ Start / ⏸ Stop / ✓ Complete / ↩ Reopen per task, bypassing every gate (paint mix, roles, interlocks). Every tap is logged with times — that log becomes the real step-time data for the scheduler.
  • ⚠ Force Oven Clear (twin header or the oven panel): resets every Running bake to Pending — un-jams a locked oven; nothing gets marked complete.
  • ⤴ Waiting on a press (panel at the top, added 07/30/26): every order whose CURRENT coat is fully ticked. These are not being worked — a stopped step marks that step done, and the COAT only moves on a separate press. That press is what takes a finished order off this floor, which is why orders sat here with every box green. Each row carries its own advance button; “last coat — this finishes the order” means the press completes it, “waits for the other stream” means poles or parts still have coats to run and it correctly stays. Every press still PINs and still runs the QC gate.
  • The prompt after the last step of a coat: stop the final step and the floor now says what happens next — advance to the next coat, or run QC and send the order to WMS Packing — with the button right there. “Not yet” dismisses it.
  • Who PIN'd every step: the order popup shows ▶ Maria · 9:14 from the Start and ■ Maria · 9:52 · 38m from the Stop. A step reading Complete with no name is outlined red — it was completed by something other than a PIN'd stop (a station card, a force-complete, or a pre-manual-mode write). That is how a forgotten PIN becomes visible instead of inferred.
  • Final-step QC gate: completing the last coat asks GOOD vs SCRAP.
    • Stock builds: the good count is what posts to NetSuite (the WO's assembly build receives GOOD pcs into the home bin).
    • Custom sales orders: ANY scrap blocks completion, red-flags the supervisor, logs the operator out. Customs can never quietly ship short.
    • Scrap > 0 writes an ⚠ SCRAP log entry pointing at the Setup Queue's ⟲ Re-make panel.

5 · WMS — Pick Queue

  • Cards appear when finishing hits ▶ Start Setup. Tap anywhere but START PICKING to expand the parts table (item · bin · qty).
  • Bins are LIVE: pulled from NetSuite when a card expands or picking starts (⟳ Live re-pulls). The big BIN readout shows the top-stock bin plus the other live bins — scanning any bin that actually holds the item passes validation.
  • ⤼ Skip This Item when a line can't be picked (phantom splices etc.) — the order completes with a ⚠ skip flag to fix at the end.
  • Staging Handshake: scan the small-parts label (+ the custom shop label when the order has one) — both must resolve to the same order before it stages for the floor.

7 · Plating — two front doors, one weekly shipment

Stock pulls (as today)

"Needs Plating" cards → Pull & Plate moves stock from its bin to plating WIP (bin transfer, status WIP-Plating) and stages the line.

📥 OB Plating — custom outgoing

  1. Shop completes a custom order with a /MEP, /EP or /P25 finish → operator carries the pieces to the OB PLATING bin (label printed).
  2. WMS → Plating → 📥 OB Plating section: scan the shop WO label (or tap 📥 Into OB Plating) — the piece stages in the bin, plating tag prints, vendor resolves from the finish.
  3. Pieces accumulate all week; the section lists what's riding.
  4. Weekly 📦 Ship: ONE plater PO (every piece itemized in the description) + packing list + pallet label — customs and stock pulls together. Set the plating $ on custom lines via the ship modal's cost override. Mixed vendors ship separately.

8 · Shop Floor — custom fabrication

  • Staged → Active: one active order at a time; ▶ Start brings a staged order over.
  • Multi-configuration orders: per-config checkboxes with 🔍 View Item (open → view → make → check).
  • In-house finish orders: "Parts Require Phosphate" checkboxes ride the router — Complete warns if unchecked.
  • Outsourced finish orders (/MEP //EP //P25): Complete = "send to OB PLATING" (see §7). Once-only — undo/re-complete can't duplicate the queue entry.
  • Reprint Label on Recently Completed when the printer eats one; UNDO — Back to Production reverses an accidental Complete and re-blocks staging.
  • SOPs: built in 1.6's dedicated SOP slot → annotated pages in Tab .6 → viewable from BOM Engine + the floor (📋 button), 3D or PDF.
  • Routings tab: base assemblies only (nothing with a "/"), Classical Elements + M2C only.
  • Programs tab: ⚙ Step-by-Step on each program card = the machine-start data sheet (labels + exact control values + machine-screen photos), built in the program editor.

9 · Quick Ship (HQ tab 7)

  • Pattern kits: one kit per pattern; the customer's finish picks the /CODE variants at add time. Kits filed in collections (tap a collection to open).
  • Kit pricing: base + per-customer overrides; the cart reprices live; kit price distributes across NetSuite lines (accounting stays itemized).
  • Invoices: customer pays against kit # + kit price; components print as unpriced sub-lines. "Match NS Invoice #" ties the NetSuite invoice number on; print/email from the CRM card.
  • Flow discipline: Pick (STOCK tab) → Pack (PACKING tab, photo) → Ship — ring-pack lines pull singles ("→ pull N × …-EA") and the pack assembly builds post at Mark Picked.

9.5 · Customer pricing, fees & checkout add-ons (HQ 4.6) — added 07/29–31/26

One screen for “what does THIS customer pay for THIS collection”, plus the fee catalogue behind the add-on step at checkout. It replaced re-uploading a spreadsheet to change one number.

Two stores, and which one CPQ reads

WhereWhat it drives
Customer Alias & Pricing
(the box on the item; Master Library, and ⚙ P / EP in 4.6)		The CPQ price levels. Painted and plated tiers side by side, each with cost / wholesale / retail, plus their part #s. Used when the quote's price level is Fabricut Cost / Wholesale / Retail.

Both are live — the price level on the quote decides which applies. At Standard the box is never consulted; at a Fabricut level the box overrides client pricing and base price alike. An edit in 4.6 writes BOTH, so they cannot drift. It never creates a box on an item that has none, a variant writes its own values rather than moving its siblings, and pattern #s and the “$0 · w/ arm” flags are never touched.
  • Collection mode — pick a customer and a collection: every part, with base price, their SKU, their net, their sales, their retail. Edit in place, one Save. Filters for ALL / Priced / Not priced; the counter is your gap list.
  • Fees & Add-ons mode — the brand's whole fee catalogue (fees are brand-wide, not collection-scoped, which is why they never showed under a collection filter). Adds: how it's charged, unit, %, min $, and a PORTAL tick.
  • The row shows the tiers — PAINTED 35 · 70 · 140 PLATED 43 · 86 · 172 # H1-FRPF / H1-FREPF. A fee missing its premium price is obvious by its absence. $0 prints as $0 (included with the arm); blank means no price at that tier.
  • Searching for something not in the collection offers to add it — this is how a fee joins FABRICUT H1, since fees are rarely tagged.
  • Suggestions in brass = numbers already in the pricing box but never written as customer rows, so nothing quotes from them yet. “Adopt” makes them real.
  • Import Control File reads a customer's workbook and shows a DIFF — new / changed / same / not-in-library — before writing. Blank cells are “no opinion” and can never erase a price. Base prices stay out unless ticked.

Fees: four shapes, not one price

ShapeSet it asExamples
Flat per unitFlat × quantity, unit “each”cover plate · packaging · flat-rate shipping
Per named unitFlat × quantity, unit per return / foot / bend / strike-offreturns · traverse track per foot · arch bend
% of orderPercentage, % filledoutdoor coating 25%
% with a floorPercentage + Min $“10% or $100 minimum” = 10 in %, 100 in Min $
A PERCENTAGE fee is worked out from the configuration subtotal — parts and labour, net of trade discount, BEFORE any other fee and before shipping. So two percentage fees on one order never compound, and adding shipping cannot inflate a rush fee.

Add-ons at checkout (CPQ)

  • The last panel before Submit Quote to Pipeline. Fees nobody wants to model as a flow step — rush, packaging, shipping, strike-offs, colour upcharges — are picked here and each becomes its own line on the order.
  • A per-unit fee takes a quantity (the unit says what you are counting); a percentage fee is a tick. Every selected row prints its own arithmetic — 2 returns × 40.00, 10% of 400.00 = 40.00 — below the 100.00 minimum, so the minimum applies.
  • Prices come from the same resolver the quote uses, so the picker and the quote cannot disagree. Fees a flow already bills are untouched.
  • The Portal tick per fee decides whether a customer can pick it themselves; leave it off for internal-only fees.

＋ New fee creates the fee item and the customer's association in one action. Don't create one for the cover-plate upcharge — CPQ already charges the difference when a coverplate replaces the standard backplate, priced on the CP/RCP plate items; give it the customer's code in Collection mode instead.

10 · NetSuite sync — the 11.1 controls, how writes travel & how to read trouble

The two direction cards (11.1) — added 07/28/26

Every field is now a checkbox in both directions, on the card that governs it. The three custitem flags used to travel one way only — down — which is why correcting the Stocked flag in the app changed nothing in NetSuite or the Stock View report. Checkbox choices are remembered; the item scope is not.

CardWhat ticking means
Sync Master Library
“NetSuite may overwrite…”		NetSuite wins on items the app already has. Un-tick a field to FREEZE the app's value through an import — cost, price, weight, the three flags, outsource action, part handling, UOM, BOM revision, bin, vendor name/part, the NS collection/watchlist/projection blob. New items always take everything (nothing to overwrite on a first import). Item name, category and routing type stay app-master as they always have.
⬆ Push Items → NetSuite
“Write to NetSuite…”		Writes the app's value onto the NetSuite item: item #, display name, base price, weight — each now switchable — plus custitem27 (Stocked), custitem26 (In-House) and custitem28 (Old), which could not be pushed at all before.
A checkbox push is never blind. Before writing, the run reads NetSuite's current custitem26/27/28 for every matched item and the confirm shows both directions — 74 will be TICKED, 3 will be UN-TICKED, 994 already match. Read the UN-TICKED number before you accept: it means the app disagrees with NetSuite in the other direction. A flags-only run (core fields un-ticked) writes only the items that actually disagree, and if the read fails the push aborts rather than guess.

Item # scope — sync or push only what you're fixing

  • One box above both cards, applying to both directions. Blank = the whole catalog.
  • H1- item # contains it · H1-,H2- either · H1-1BE..H1-9 an item-# range.
  • The box turns brass and states the scope in words whenever it's set. It is deliberately forgotten between visits — a remembered scope would silently narrow somebody's next full sync.
  • A scoped run never creates a NetSuite item outside the scope. BOM components outside it still resolve from items already in the library.

Premium means OUTSOURCED FINISH, not “/EP” (corrected 07/29/26)

Every tier test used to be “does the suffix start with EP”. /P25 is an outsourced plated finish whose suffix starts with P, so it was read as an in-house paint and priced off the PAINTED tier — half price on a quote, the wrong pattern #, and the importer STAMPED it that way. The rule is now “is this suffix an outsourced finish”, reading the configured Outsourced Master Finishes plus /P25, so a new outsourced code is premium everywhere the day you add it.

  • 🔧 Repair Premium-Tier Prices (/P25) — walks the library and rewrites only the variants provably mis-stamped, from the plated tier already on their own base item. Prints the full list before writing, never touches numbers edited by hand, and is a no-op once clean. Safe to re-run.

Recipe: an item is right in the app but missing from the Stock View snapshot

  1. Confirm the app's own Stocked box is right (Mass Update → tier filter /P → Set Stocked Finished Assembly).
  2. 11.1 → Item # scope H1-.
  3. Push card → None, then tick Stocked · custitem27 only.
  4. Push. Read the counts in the confirm — if it wants to UN-tick hundreds, cancel and check the app values first.
  5. Re-open the Stock View snapshot. It reads NetSuite live, so no re-sync is needed.

How writes travel

  • Writes don't fire live — they stage into a queue drained about once a minute, serial, with automatic retries. This is what keeps 40 users from tripping NetSuite's ~5-connection limit.
  • Memo marker [app push 07/20/26, 2:32 PM #aVNdVI]: shows when the app pushed a transaction and doubles as the anti-duplicate token.
  • Learned payload rules (already automatic): WO creation uses assemblyItem; non-WIP work orders complete via the WO-linked Assembly Build (= NetSuite's Create Build button); receive bins are a single bin.
  • If a build 400s with "configure the inventory detail in line 1 of the component list": the raw component needs a preferred bin in NetSuite → set it → ↻ Retry.
  • Functions never auto-deploy. Server-side changes go live only via Cloud Shell:
    cd ~/ce-m2c-design-app && git pull && firebase deploy --only functions --project ce-m2c-design-collab
