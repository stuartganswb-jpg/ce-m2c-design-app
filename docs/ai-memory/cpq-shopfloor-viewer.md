Decided 2026-06-15: **abandon the compiled-PDF "paperwork roll-up."** Instead the configured item's data stays associated with the quote and is made ACCESSIBLE live across the app. A shared read-only viewer (`src/components/Shared/ConfiguredItemViewer.js`) opens from a button in THREE work-order windows (owner chose Shop + Finishing + HQ): shop floor `ShopFloor.js` CustomCard (`order.quoteId`), finishing `FinishingFloor/SetupQueue.js` card (`wo.quoteId`), and HQ `RTGDispatchTab.js` SO card (`so.hqJobId`). It renders the model LIVE (orbit/zoom, no editing — it's a confirmed order) beside the engineering-spec roll-up; tablet layout. This also retires the broken 📷 PNG capture — the floor spins the real model instead.

**How re-render works (the key fix):** at CPQ Add-to-Cart, `handleAddToCart` snapshots the resolved render onto the line item — `renderState: { cadUrl, textureEntries:[{target,url}], visibilityEntries:[{target,visible}], cloneSpecs }` + `visionPicks` (FLAT bracket/backplate ids only). The viewer rebuilds the node-name→value maps from the entry arrays in memory for DynamicModel. ⚠️ Two Firestore "cpqData contains an invalid nested entity" traps, both hit+fixed 2026-06-15: (1) don't save the raw Vision `spatialData` blob — canvas nested-arrays (use flat `visionPicks` instead, 46b05a4); (2) don't store the texture/visibility overrides as MAPS — their keys are GLB node names like "Bracket.001" and **Firestore forbids `. ~ * / [ ]` in field/map-key names** — store as entry-ARRAYS so node names are unrestricted array values (8c76bad). `handleFinalizeQuote` also runs `fsSafe()` over all of `cpqData`+`engineeringNotes` (strips undefined/NaN/class-instances/nested-arrays) and a `findFsViolation()` diagnostic logs `[CPQ finalize build-X]` to console. It rides `cpqData.cartItems` into `jobs/{jobId}` verbatim. The viewer reads `jobs/{quoteId}`, feeds renderState straight to the exported `DynamicModel` — NO live recompute, so the order renders frozen-as-sold even if the flow/assembly is later edited (that geometry-map drift was the blocker; snapshotting sidesteps it). `DynamicModel` + `EngineeringSpecsStrip` are now `export const` in CPQTab.js. Parts for spec name-resolution come from a one-shot `getDocs(Approved_Designs)`.

The viewer now shows the FULL roll-up (confirmed working 2026-06-15): live 3D → **Bracket Locations & Notes** (placed right after the model, brass border, so drill notes aren't buried) → engineering specs (`EngineeringSpecsStrip`, with `hideHangers` so it doesn't duplicate the bracket panel) → Bill-of-Materials/router (from line `pricingBreakdown`) → Vision shop drawing (`draftSvg` inline). Notes come from three snapshots on the line item: `engineeringNotes.hangerLocations` (bracket/splice positions + the `att.note` text), `bracketNotes` (the raw per-pin note boxes, fallback if hangerLocations is empty), and `generalNotes` (free-floating canvas `shopNotes`). `bracketNotes`/`generalNotes` are going-forward (added 2026-06-15). Lesson: data was present but the panel was below the fold → "missing" was a layout problem, not data.
