**Cluster region-tag system (shipped 2026-06-13, commit f44740e on main/prod).** Built to make CPQ flows easy: instead of hand-picking ~49 per-part clusters to isolate a config (the thing that kept breaking the FI flow work), Node Grouping now tags clusters by **Location** (WALL/CEILING/END) + **Position** (LEFT/CENTER/RIGHT, auto from geometry), and the flow builder toggles a whole region in one click.

**Architecture (user chose "keep per-part + region tags" + "assisted"):** clusters stay **per-part** (one cluster = one part code's instance) so **BOM Auto-Assign keeps matching cluster.name→library-part** — the cluster NAME stays part-based. Region info lives in NEW additive fields: `location`, `position`, `center` (centroid persisted). Downstream (CPQ `visibilityOverrides` CPQTab.js:1163, BOM Auto-Assign VisualAssemblyTab.js, packaging) only read id/name/nodes → unaffected. Old clusters with no location fall under "UNGROUPED".

**NodeClusterTab.js:** Auto-Group is now a **right-docked panel** (no blocking popup) beside the live 3D — `showAutoPanel` renders a `position:fixed` right panel, not a fullscreen overlay. Per-proposal **Location tag** buttons (WALL/CEILING/END) seeded by `guessLocation()` (prefix guess: FIW→WALL, FIC→CEILING, FIIM/END/INSIDE→END; '' when ambiguous like shared backplates). **Bulk-tag** the checked proposals. Click a proposal row → `setPreviewNodes(p.nodes)` → the 3D `SelectableModel` highlights it (viewer prop `locatingNodes={previewNodes.length ? previewNodes : locatingNodes}`). `handleAutoSaveSelected` writes `{position, location, center}` onto each cluster. Existing clusters re-taggable via Location buttons in the "Saved BOM Bindings" panel (`handleSetClusterLocation`). Exports `regionLabel(cl)` → "WALL · LEFT". `LOCATIONS = ['WALL','CEILING','END']` (extend for other product lines).

**AdminTab.js Hide-Geometry checklist:** now groups clusters by `${location}|${position}` under **region headers** with a parent checkbox (checked=all hidden, indeterminate=some) that adds/removes the whole region's ids to `flowSettings.hiddenClusters`. Ungrouped clusters render flat under "UNGROUPED". So building a wall flow = hide the CEILING + END region headers (a few clicks) instead of 49 checkboxes.

**To use (after FI rebuild):** upload glb → Node Grouping → Auto-Group → tag Wall/Ceiling/End per region (L/C/R auto) → Save → flow builder Hide-Geometry shows region toggles. See [[flat-iron-3flow-build]] for the FI part decode + the per-flow hide rules.

**Auto-Group visual/edit refinements (commits c403575 "visualize groupings", 967dd5e "click-to-reveal + edit membership"):** the docked panel now (a) paints each checked proposal its own color in the 3D ("◧ Colors on" toggle, `GROUP_COLOR` hue/index) with a matching swatch + left accent bar per row; (b) click a part in 3D → isolates its group + the row; click a row → isolates that group (`previewProposalId`); (c) per-row **✎ Edit** toggle (`activeProposalId`) → while editing, clicking meshes in 3D add/remove them from that group (`proposalNodeOverrides`, a part lives in one group; pulled out of others); edits flow into saved `nodes` ("· edited" badge). All in NodeClusterTab.js.

**Library-driven Category + Location + hover-glow (shipped 2026-06-14, commit f574955 on main/prod).** Auto-Group now matches each node to a library component — fuzzy: cleaned base name + node names vs item `legacyErpId`/`itemId`/`itemName`, normalized (`matchLibrary`/`libraryIndex` in NodeClusterTab; loads `partClass=='Inventory'` for the brand). From the match it pre-fills: **Category** (BRACKET/POLE/FINIAL/BACKPLATE, from `manufacturingSpecs.productType`) — a NEW field saved on each cluster alongside location/position — and **Location** for brackets from `manufacturingSpecs.customData.bracketType` (wall→WALL, ceiling→CEILING, inside-mount→END). **Backplates** have no intrinsic location: each inherits the Location of the geometrically nearest LOCATED bracket arm (post-pass in the `autoProposals` useMemo; trigger = productType "BACKPLATE"). Falls back to `guessLocation`/`guessCategory` when no match. Each row shows the resolved match (⛓ item · type · mount, ≈ for fuzzy) + ↳ backplate inheritance; bulk **⛓ From Library** fill. **Color system changed:** always-on group colors now OFF by default — instead **hover a part or row → that part + its whole group glow** (others fade) via the isolate path (`glowNodes` = editing‖hovered‖clicked group; `handleAutoMeshHover` on `onPointerMove`; ◧ Color-groups toggle still available). **List filter:** studio now lists only `routingType==='MAIN'` assemblies (mirrors BOM Engine) so components mis-classed as Assembly (finish-variant screws) no longer leak in. **Hardening:** `isDescendantOf` is null-safe (skips clusters with missing `nodes`) so a legacy malformed cluster can't blank the 3D viewer. **Verified end-to-end 2026-06-14 on the rebuilt FI model:** Node Grouping + BOM Engine both work.

**LEFT/RIGHT by SCREEN direction (fix 2026-06-15, SHIPPED to prod `7820ca8`, owner-verified on BRIMAR + Flat Iron).** Auto-Group's `positionLabel` used to sort along the model's longest WORLD axis → mirrored/rotated assemblies (CE BRIMAR) labeled the wrong side. Now it sorts by projection onto the viewer's fixed **screen-right** vector (camera `[5,5,5]`→origin ⇒ `(1,0,-1)/√2`), so left-on-screen = LEFT for every model. Don't reintroduce world-axis ordering. Safety net: a per-assembly **`nodeOrientationFlip`** flag (on the Approved_Designs doc) toggled by the "⇄ Flip L/R" button in the Auto-Group panel header reverses the order live (it's in the `autoProposals` dep array). Same commit pins the 3D viewer (`position:sticky`, bounded to viewport height) with the right column scrolling independently, so the model stays visible/draggable on long (20+ part) BOMs.
