Goal (user, 2026-06-17): WMS processes that turn raw stock into finished finishes, reflected in NetSuite WITHOUT Work-Order/WIP overhead. Base ex: CE brand `H1-138BF` (raw inventory item, lives in a bin). Two tracks:

**Track 1 — in-house phosphate (fast).** `H1-138BF` → assembly `H1-138BF/P` (suffix `/P` = phosphated; cf. `/EP`=plated convention already hardcoded in NetSuiteSyncTab). One NetSuite **Assembly Build**: consume base from raw bin, yield assembly into phosphate bin. Operator scans source+dest bins. No WO.

**Track 2 — outsourced plating (3–4 wk round-trip).** The only "WIP" is a non-available **Inventory Status** (their NetSuite HAS Inventory Status on; "Good" = the available one). Loop:
1. Pull/scan out of raw bin → **Inventory Status Change** Good→WIP-Plating, raw bin→plating bin (drops from Available, stays on-hand/owned).
2. Pack box (barcode) + pallet — app only.
3. Ship weekly pallet → app vendor PO + shipment label; **Purchase Order** in NetSuite to Dayton Grey, ONE summary line "Weekly Plating Shipment" = Σ plating cost (one standard PO per shipment, NOT a true blanket PO).
4. Pallet returns → **Item Receipt** vs that PO (enables vendor bill).
5. Scan each piece into finished bin → **Assembly Build** of plated SKU consuming base from WIP-Plating status/plating bin → finished bin Good. Clears WIP. (If a build can't consume a non-available status, add a status-change WIP→Good at the plating bin first — still no WO.)

**NetSuite IDs (user-supplied 2026-06-17) — CE brand = subsidiary 2 / location 17:**
- Dayton Grey vendor internal id = **83361**
- "Weekly Plating Shipment" service item id = **61947** (the summary PO line)
- Inventory STATUS internal ids (user-confirmed 2026-06-17, these are the REAL record ids): **Good = 1** (available, the from-status raw stock sits in), **WIP-Plating = 13** (non-available, the to-status). NOT 14 — "Good - Available"=14 was the wrong record (NS rejected it). On return (Phase 4) go WIP-Plating(13) → Good(1).
- Inventory Adjustment account = 254 (see [[netsuite-app-master]])
- Bins: come from the item records (`binLocation` / `manufacturingSpecs.binLocation`) — no separate bin map; source bin = base item's bin, dest bin = assembly's bin.
- Finished assemblies + BOMs (`H1-138BF/P` etc.) ALREADY exist in NetSuite with the base as a component.
