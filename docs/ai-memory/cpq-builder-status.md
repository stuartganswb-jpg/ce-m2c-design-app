CPQ is the priority going forward — it drives the entire app workflow; the rest of the site gets refined after CPQ is right. Work lives on branch `feat/work-order-contract` (PR #1). Clean handoff state: branch pushed, PR open, every change builds clean (`CI=false react-scripts build`), preview is testable (App Check debug token registered — see [[work-order-contract-impl]]).

CPQ flow builder step types (AdminTab) + configurator render/pricing (CPQTab) now support:
- DROPDOWN, VISUAL_GRID, VISUAL_DIMENSIONS, DIMENSIONS, STATIC_FEE, and **STYLE_SWAP** ("Choose / Swap Style").
- STATIC_FEE = a fee: no part/routing required; value rolls into the flow's NetSuite rollup item.
- **STYLE_SWAP**: items + per-item base price + 3D mesh nodes are all sourced from the linked Master Assembly's BOM pins (`assembly_pins.targetNode`). Auto-builds `geometryMap` (mesh visibility toggle) + optional Finish dropdown scoped by `finishAllowedOptions`. The generic Item Mapping/Base Price + Target Mesh windows are hidden for this type. User confirmed working on first test.
  - Per-style-option fields: `price` and `layerZ` (2D-layer stacking override, honored by get2DRenderLayers — raise above the pole so a loop bracket paints in front).
- Flow-level config: **Fabrication Preset** = `fabShape` (bay config: STRAIGHT/MITERED/BOW) + `fabEndStyle` (FINIAL/RETURN_BEND/RETURN_MITER) + `fabProjection` → drives Vision, authoritative. **NetSuite rollup item** (`nsRollupItemId`, created via the Flow Builder button), plus legacyErpId/basePrice/linkedAssemblyId.
- Flow matrix to build (each = its own flow + fab preset + rollup item): bay {Straight, Mitered, Curved Bay} × end style {Finial, Bent Return (FR), Miter Return}. Only Straight+Bent Return (BRIMAR FR) built so far. Vision bay label was "Curved Bow", now "Curved Bay".

Auto-Group replace-in-place (shipped prod 2026-06-11, PR #4): re-running Auto-Group (NodeClusterTab) now matches each proposal to an existing cluster by SANITIZED node-set overlap (>=0.6) and reuses that cluster's id (refreshing name+nodes) instead of appending a duplicate. Reusing the id keeps assembly_pins linked → existing STYLE_SWAP steps pick up the refreshed cluster name/label (L/C/R) WITHOUT re-assigning pins. Verified 16/16 exact (1.00) match on CE-ASM-5865's old `1IN_LOOP_BRACKET_EXT_V41`-style clusters. **Node-name format gotcha:** the CPQTab configurator's 3D matcher (DynamicModel, ~line 101) compares `child.name.toLowerCase()` to the targetNode via `===`/`startsWith(t+'_'|'.')` — i.e. it matches RAW glb mesh names ("body1.005"). So cluster/pin `targetNode` MUST be raw names (what Auto-Group writes), NOT sanitized ("body1005" won't match). Older clusters/pins stored sanitized names (stale for the current raw-name glb); replace-in-place refreshes them to raw. After re-grouping, re-assign pins in Visual Assembly so new pins carry raw targetNodes for correct 3D/finish behavior (the L/C/R label itself shows without re-assigning, via clusterId reuse).

STYLE_SWAP per-instance identity (shipped to prod 2026-06-11, PR #3): a part that repeats at multiple positions (loop bracket L/C/R) used to collapse into one all-or-nothing checkbox because options were keyed by `partId`. Now each style option carries a unique `optId` = `pin.targetNode || pin.clusterId || pin.partId` (targetNode is always unique per instance; clusterId can be shared in legacy data). Builder (AdminTab) keys styleOptions/geometryMap by `optId`; configurator (CPQTab) consumes `o.optId || o.partId` everywhere (getOptionsForStep id, pricing find, layerZ, geometry/visibility) with partId fallback for legacy flows; the quote/ERP line resolves the real `partId` from the chosen styleOpt (NOT the optId) so NetSuite mapping stays correct. Each builder row is labeled from the matched nodeCluster name (`linkedAsm.nodeClusters.find(c=>c.id===pin.clusterId).name`, underscores→spaces). **Label caveat:** CE-ASM-5865's existing clusters are named `1IN_LOOP_BRACKET_EXT_V41/V42/V43` (older clustering pass), NOT my Auto-Group's friendly `— LEFT/CENTER/RIGHT`. To get true L/C/R labels in the builder, re-run Auto-Group (Split by Position) on the assembly and re-assign pins in Visual Assembly; new Auto-Grouped assemblies show L/C/R automatically. assembly_pins carry `clusterId` (=cluster id, set by Visual Assembly assign) and `x/y/z` (currently all 0 — can't derive position from pins; comes from cluster/geometry).

Per-option finish scoping (branch `feat/flat-iron-cpq`, commits e159be1/e0d4dd8, NOT yet merged): a STYLE_SWAP option can carry its own `finishAllowedOptions`; CPQTab's compound Finish sub-picker narrows to the selected option's list (falls back to step-level `finishAllowedOptions`). Switching the style now clears the paired `__finish` (a finish valid for one style can't carry over to/mis-texture another). AdminTab has a "Per-style finish overrides" editor that iterates `styleOptions` directly (so hand-authored options that aren't BOM pins are editable). Built for the FI in-flow Wood-vs-Metal rod choice (Wood → wood-clear finishes, Metal → metal finishes) — reusable for H1 collections. See [[flat-iron-3flow-build]].

**Flow-builder BOM-load fix (branch `feat/flat-iron-cpq`, commit d04ca58, not merged):** the STYLE_SWAP editor showed "No BOM components found" for the FI flows because AdminTab resolved the linked assembly from `masterAssemblies` (filtered to partClass 'Master Assembly' OR a CPQ routingType). M2C-ASM-6776 is partClass 'Assembly' with NO routingType set → excluded → `linkedAsm` undefined → pins + nodeClusters never loaded. Fixed: resolve `linkedAsm` from `allApprovedDesigns` (by id|itemId) at all 3 sites — a linked flow shouldn't be re-filtered. Lesson: setting an assembly's Parent Routing (routingType) is what classifies it as a CPQ master; the builder no longer depends on it. Also added a "Configured Options" panel atop the STYLE_SWAP editor (lists current styleOptions w/ thumbnail + remove ×) so hand-authored non-pin options (Wood/Metal rod — no library part exists for the poles) are visible/editable, not invisible. CAVEAT remaining: there's still no builder UI to ADD a custom (non-pin) option — Wood/Metal were script-authored; to make them first-class, create library parts for the poles + pin them, or add a "+ custom option" button.

Known CPQ caveats / candidate next features (user has more in mind):
- STYLE_SWAP finish has no upcharge pricing — only the style item prices. Add per-finish price if needed.
- ERP estimate line rate uses `clientPricing.price` (kept consistent with the CPQ quote total); open decision whether it should be `clientSalesPrice`.
- Fab preset drives projection only; bracketW/thickness still come from the selected part — may want a bracketW preset too.
- RESOLVED (branch `cpq-caveats-cleanup`, commits bcda0d1/4a8404b, not yet merged): `renderOptionPrice` now shows the STYLE_SWAP per-option `opt.price` (mirrors the live calc at CPQTab.js:616), and the legacy `master_lists.customers` unfiltered merge was dropped from `combinedCustomers` — CPQ customer dropdown is now purely brand-isolated `crm_records` (user chose "drop the legacy merge"). Risk to watch: any customer that lived ONLY in the legacy list (not migrated to crm_records) no longer appears.
- The 3D visibility/texture logic was written without local 3D testing — keep validating on preview.
- CPQ 3D view = react-three-fiber/useGLTF rendering the actual .glb with finish textures applied to mesh materials (NOT 2D PNGs; the 2D mode + Style Swap layerZ is a separate flat-PNG fallback). Fusion-exported .glb ships steel as `alphaMode: BLEND` → three.js treats it transparent → ring renders behind pole. DynamicModel now force-opaques materials that are flagged transparent but fully opaque (opacity 1, no alphaMap). Best long-term fix: export steel as Opaque from Fusion.
- .glb mesh names are generic (Body1, Body1.001…); semantic names (2.125 RING, BUSHING-BRIMAR, Mount Plate, 1in Loop Bracket Ext) are on parent nodes. Renderer matches visibility/texture on MESH name — target Body1.xxx.
- Fusion-exported .glb is inches/mm: root node scale 0.0254, inner nodes 0.3937, nested ~8 deep. Anything moving meshes must work in WORLD space then convert back via parent.worldToLocal (InstructionsTab exploder was moving local position by a world delta → ~1% movement; fixed). All their assemblies share this structure.
